Las bases de datos embebidas se tratan de aquellas bases de datos las cuales no necesitan de un servidor independiente para poder llegar a funcionar, ya que estas se ejecutan dentro del propio programa, lo que hace que sean útiles al querer guardar información de manera local. En el ejercicio se han usado HSQLDB, H2 y Derby mediante la API de JDBC para poder trabajar con la información de la academia.

HSQLDB se caracteriza por ser una base de datos desarrollada totalmente en Java la cuál permite almacenar su información tanto en memoria como en disco, su principal ventaja es la de poder integrarse fácilmente con nuestro programa mediante JDBC. Como inconveniente tenemos que al usarla únicamente en memoria los datos se perderán al cerrar la base de datos, por lo que este modo nos serviría para probar las inserciones o eliminaciones de alumnos sin afectar a los datos que tengamos guardados en disco.

H2 al igual que HSQLDB permite guardar información en memoria o mediante ficheros, pero cuenta con la ventaja de tener una consola web mediante la cuál podremos consultar las tablas y comprobar la información que contienen. Esto nos resultaría útil en el ejercicio al querer comprobar si un alumno o una asignatura se ha insertado correctamente, pero cuenta con la desventaja de que algunas sentencias SQL pueden funcionar de manera diferente respecto a otros gestores.

Derby por su parte permite establecer una base de datos embebida en Java y guardar la información de manera permanente sin necesitar de un servidor, por lo que se podría usar para conservar los registros de la academia y volver a consultarlos al ejecutar nuevamente el programa. Como inconveniente tenemos que actualmente Derby ya no recibe mantenimiento activo, lo que hace que sea más recomendable para programas existentes que ya usen este gestor.

Respecto a los conectores los tres gestores cuentan con soporte a la API de JDBC, esta API lo que hace es dar una estructura común para poder establecer conexiones y ejecutar las operaciones CRUD de una manera similar. La diferencia se encuentra en que cada uno necesita de su propio driver dentro del pom.xml y de su URL correspondiente, por lo que al cambiar de gestor se tendría que adaptar la conexión y comprobar que las sentencias SQL sigan funcionando correctamente
